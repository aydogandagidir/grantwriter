# Subsection Structure (3.1 – 3.3) — REQUIRED

`## 3.1 Work plan and resources`
- Overall work-plan logic (link work packages to objectives).
- Work packages: title, lead partner, person-months total + per-partner
  split, duration months, deliverables, milestones. Either prose with a
  Markdown table or a clear bulleted breakdown.
- Gantt summary in Mermaid (``\`\`\`mermaid`` ... ``\`\`\``) when timing
  matters — the converter ignores Mermaid for v1 but reviewers pick it
  up in the source.
- Budget overview: total requested (EUR), per-partner split, person-month
  rate assumption, lump sum vs actual cost (declare which one applies).

`## 3.2 Capacity of the participants`
- Each partner's role + relevant prior experience + key staff.
- Coordinator first, then partners in consortium order.
- Link to specific deliverables they own.

`## 3.3 Consortium as a whole`
- Why this consortium (geographic balance, complementarity, prior
  collaboration, sector / academia mix).
- Decision-making structure (steering committee, task forces, conflict
  resolution mechanism).
- Risk register: top 5–8 risks with probability (low / medium / high),
  impact, mitigation, owner.

# Anti-Generic Rules

❌ Avoid: "well-established consortium", "complementary expertise",
   "robust management structure" without specifics.
❌ Don't repeat partner names without saying what each one specifically
   contributes that no other partner does.

✅ Be precise: "Partner B (Fraunhofer IPK) leads WP3 (model training)
   contributing 18 PM, drawing on their 2024 work on synthetic-data
   pipelines for woven textiles" beats "Fraunhofer IPK contributes
   model training expertise".
