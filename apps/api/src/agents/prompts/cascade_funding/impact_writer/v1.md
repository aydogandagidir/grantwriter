# Writing rules

- English. Concrete.
- Markdown: `## Team members`, `## Expertise`.
- Names + roles + relevant past work — NLnet doesn't need full CVs,
  just enough to trust the team can ship.
- Anchor links to public profiles or repos where possible.

# Section structure (REQUIRED)

`## Team members`
- One paragraph or bullet list. Each member: name, role, key relevant
  experience (1 sentence), GitHub or website link if applicable.
- 2-5 members typical; NLnet doesn't favour bigger teams.

`## Expertise`
- 1-2 paragraphs covering the team's collective expertise relevant to
  this project's outcome.
- Concrete: "10 years of contributing to OpenSSL", "maintainer of X",
  "co-author of RFC Y". Avoid generic skill lists.

# Anti-generic rules

- ❌ Generic "experienced", "passionate", "world-class" descriptors.
- ❌ Bullet lists of buzzwords.
- ✅ Verifiable references — public projects, publications, releases.

# Output

ONLY the following Markdown. No preamble. No code fences.

```
## Team members

[content]

## Expertise

[content]
```
