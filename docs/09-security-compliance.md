# 09 — Güvenlik ve Compliance

## 1. Tehdit Modeli

Bu uygulama dört uyumluluk rejimine aynı anda tabi: **KVKK** (Türk müşteriler), **GDPR** (AB müşteriler), **EU AI Act** (sistemimiz "limited risk" kategorisinde — açıklama yükümlülüğü), **Horizon Europe AI Disclosure** (sayfa 32, çıktı kullanıcı tarafından submit edilirken zorunlu). Bunların hepsi farklı şeyler — KVKK/GDPR veri koruma, AI Act sistemin kendisi, HE disclosure çıktının nereye gittiği.

Tehditleri STRIDE çerçevesinde haritaladık. Aşağıdaki başlıklarda her birinin kontrol katmanı listeleniyor — ekibe net mesaj: bu kontroller PR review sırasında checklist olarak kullanılacak, eksiklik blocker.

### STRIDE haritası

| Tehdit | Vektör | Kontrol |
|---|---|---|
| **Spoofing** (kimlik taklidi) | Çalınan JWT, OAuth bypass | Supabase Auth + 2FA (admin), JWT short TTL (1h), refresh rotation |
| **Tampering** (veri değiştirme) | SQL injection, RLS bypass | Pydantic input validation, parameterized queries, RLS test suite CI'da |
| **Repudiation** (inkar) | Kullanıcı "ben yapmadım" der | `audit_log` tablosu, immutable, IP+UA dahil |
| **Information disclosure** | Cross-tenant data leak, BYOK key sızıntısı | RLS policies + RLS test, BYOK pgcrypto encryption, no key in logs |
| **Denial of service** | LLM cost amplification attack | Rate limit (10 LLM call/min), monthly proposal cap, alert thresholds |
| **Elevation of privilege** | Member→admin yetki aşımı | `auth.is_tenant_admin()` her admin rotada zorunlu, double-check service layer |

## 2. Horizon Europe AI Disclosure (Sayfa 32) — Kritik

### 2.1 Niye bu kadar önemli?

EC 2025'ten itibaren her HE başvurusunun Standard Application Form sayfa 32'sinde "use of AI tools" beyanını zorunlu kıldı. Eksik veya yanlış beyan → ineligibility riski. Bizim ürünümüz tam olarak bu beyanı otomatik doldurma vaadi üzerine kurulu — eğer kötü doldurursak müşteri ineligibility riskine giriyor, **kariyer-ölümü senaryosu**.

### 2.2 Implementasyon

`proposal_provenance` tablosuna her cümle yazıldığında source kaydedilir:
- `human` — kullanıcı manuel yazdı
- `ai-generated` — bir agent üretti
- `ai-edited` — agent üretti, kullanıcı düzenledi
- `imported` — başka bir kaynaktan kopyalandı (örn. brief)
- `rag-retrieved` — RAG ile getirilen örnek pasajdan adapte

ComplianceReviewer agent draft tamamlandıktan sonra bu tablodan istatistik çıkarır:

```python
async def generate_ai_disclosure(proposal_id: UUID) -> str:
    rows = await db.fetch_all("""
        SELECT source, agent_id, llm_model, count(*) as count
        FROM proposal_provenance
        WHERE proposal_id = $1
        GROUP BY source, agent_id, llm_model
    """, proposal_id)

    stats = aggregate(rows)
    # stats = {
    #   "total_sentences": 412,
    #   "human": 89,
    #   "ai_generated": 287,
    #   "ai_edited": 36,
    #   "agents_used": ["excellence_writer", "impact_writer", ...],
    #   "models_used": ["claude-opus-4-7", "claude-sonnet-4-6"],
    # }

    template = load_prompt("compliance/ai_disclosure_template.md")
    return template.format(**stats)
```

Çıktı şablonu (özetle):

> **Use of AI tools in this proposal**
>
> The applicant used Bluedev GrantWriter (https://bluedev.dev), an AI-assisted grant
> writing platform, to draft this proposal. The platform uses {models_used} via
> {provider} for content generation, with retrieval-augmented generation from a
> corpus of {corpus_size} successful past proposals.
>
> Of {total_sentences} sentences in the proposal:
> - {human} were authored directly by the applicant
> - {ai_generated} were generated by the AI tool from the applicant's brief and verified
>   reference materials
> - {ai_edited} were AI-generated but subsequently edited by the applicant
>
> All citations were verified against Crossref and OpenAlex; {verified_count} of
> {total_citations} citations were independently verified before submission.
>
> The applicant accepts full responsibility for the accuracy, validity, and
> originality of all content in this proposal.

Kullanıcı bu metni düzenleyebilir ama bizim default'umuz EC'nin önerdiği yapıya en yakın olanı.

### 2.3 Provenance bütünlüğü

Editör bir cümle düzenlendiğinde `ai-generated` → `ai-edited`'e otomatik dönüşmesi gerekir. Bu kritik çünkü kullanıcı düzenlediği bir cümleyi "AI yazdı" olarak beyan ederse yanlış bilgilendirme olur. TipTap'in transaction listener'ında implementation:

```typescript
editor.on('transaction', ({ transaction }) => {
  transaction.steps.forEach(step => {
    if (step.from && step.to) {
      // Iterate marks in changed range, downgrade ai-generated → ai-edited
      editor.state.doc.nodesBetween(step.from, step.to, (node, pos) => {
        const provMark = node.marks.find(m => m.type.name === 'provenance');
        if (provMark?.attrs.source === 'ai-generated') {
          editor.commands.updateAttributes('provenance', { source: 'ai-edited' });
        }
      });
    }
  });
});
```

Sprint 4'te edge case test paketi yazılacak: paste, undo/redo, format change durumlarında provenance doğru güncelleniyor mu.

## 3. KVKK ve GDPR

### 3.1 Veri kategorileri ve hukuki dayanak

| Veri | Kategori | Hukuki dayanak (KVKK 5/GDPR 6) |
|---|---|---|
| Kullanıcı email, isim | Kişisel | Sözleşmenin kurulması/ifası |
| IP adresi (audit log) | Kişisel | Meşru menfaat (güvenlik) |
| Şirket bilgileri | KVKK kapsamı dışı (genelde) | — |
| API anahtarları | "İşletmenin sırrı" | Sözleşme |
| Proposal içeriği | KVKK kapsamı dışı (proje verisi), ama içinde PII olabilir | Müşterinin sorumluluğu, biz "veri işleyen" |
| Stripe/Iyzico müşteri ID | Kişisel | Yasal zorunluluk (faturalandırma) |

Bluedev VERBİS'e kaydolacak — Türkiye'de 50+ çalışanı olan ya da yıllık ciro 100M TL üstü olan kayıt zorunlu, biz değiliz ama müşterilerimiz KVKK uyumluluğu için bizim de kayıtlı olmamızı tercih edecek. Bluedev için bu hafta 1 görevi (ekipten Aydoğan, ürün kodu değil).

### 3.2 Kullanıcı hakları

Aşağıdaki endpoint'ler hafta 4'te eklenecek (P1, MVP sonrası gerek olabilir):

- `GET /api/v1/me/data-export` — tüm kişisel veriyi JSON olarak indir (GDPR 20)
- `DELETE /api/v1/me/account` — hesap silme + 30 gün soft delete sonra hard delete (GDPR 17, KVKK 7)
- `POST /api/v1/me/data-correction-request` — düzeltme talebi (GDPR 16)

Hesap silinince `proposals` tablosundaki kayıtlar `created_by = NULL` olur, içerik kalır (tenant'ın diğer kullanıcıları erişebilsin), audit_log değişmez (yasal saklama).

### 3.3 PII handling

Brief alanlarında genelde PII yok, ama partner listesi gibi alanlarda olabilir. Politika:
- **Loglarda asla full brief content yok**, sadece proposal_id + section
- Sentry breadcrumb'ları otomatik scrub (PII pattern matching)
- LLM çağrısının request body'si Anthropic'e gider — Anthropic'in SOC2 + zero-retention policy'si var (Claude API for businesses)
- Müşteri istediği taktirde (Enterprise plan, Faz 3) self-hosted Mistral/Llama EU cloud opsiyonu

### 3.4 Veri lokasyonu

Supabase: AB region (Frankfurt). Vercel: edge cache global ama veri Frankfurt origin. Railway: EU-West (Amsterdam). Anthropic: US data center default; biz `anthropic-version: 2023-06-01` + EU residency talebi yapacağız (Sprint 1, Bluedev tarafı).

## 4. EU AI Act

Sistem **limited risk** kategorisinde (Article 50): "AI system intended to interact with natural persons" — sadece kullanıcıyı bilgilendirme yükümlülüğü var. Üst kategoriler (high-risk, prohibited) bizim use case'i kapsamıyor.

Kontroller:
- Marketing sitesinde ve uygulamada açık beyan: "Bu uygulama AI içerir, çıktıları kullanıcı sorumluluğunda"
- Provenance markers UI'da görünür (sadece backend'de değil)
- Onboarding'de bir kez disclaimer kabul ettirilir
- Çıktı submit'inde reminder: "AI çıktı, doğrulayın"

GPAI Code of Practice (Ağustos 2025'te bağlayıcı oldu) bizi etkilemez — biz GPAI **sağlayıcısı** değiliz, **deployer**'ız.

## 5. BYOK (Bring Your Own Key) Güvenliği

### 5.1 Tasarım

Müşterinin Anthropic/OpenAI API anahtarını saklarız ama:
1. **Şifrelenmiş saklama:** `pgcrypto` `pgp_sym_encrypt` ile, master key Supabase Vault'ta
2. **Master key rotasyonu:** her 6 ay (Bluedev internal task)
3. **Anahtar sadece runtime'da decrypt edilir**, decrypt edilen değer hiçbir log'a, hiçbir cache'e yazılmaz
4. **Frontend asla anahtarı geri alamaz** — sadece "set/not set" boolean

```python
# apps/api/src/llm/key_vault.py
async def get_anthropic_key(tenant_id: UUID) -> str | None:
    row = await db.fetch_one("""
        SELECT pgp_sym_decrypt(anthropic_api_key_encrypted, $1) AS key
        FROM tenant_llm_config
        WHERE tenant_id = $2
    """, settings.MASTER_KEY, tenant_id)
    return row["key"] if row else None
```

`MASTER_KEY` Railway env var'da, restart-time only, request log'larında asla geçmez.

### 5.2 Tehdit: master key sızıntısı

Eğer Railway env'i sızarsa attacker tüm BYOK anahtarlarını decrypt edebilir. Mitigation:
- Railway env'e access edebilen sadece 2 kişi (Aydoğan + 1 senior)
- Audit: master key decrypt çağrı sayısı normal trafikten anormal yüksekse Slack alert
- Faz 2'de AWS KMS / HashiCorp Vault'a taşıma planlandı (managed envelope encryption)

### 5.3 Anahtar test endpoint'i

`POST /api/v1/tenant/llm-config/test` minimum maliyetli bir Claude çağrısı yapar (5 input token, max_tokens=5). Anahtar geçersizse 401 döner ve kullanıcıya gösterilir; anahtar doğrudur ama ödeme gecikmiş ise 402 döner. Bu sayede kullanıcı anahtarın gerçekten çalıştığından emin olur.

## 8. Rate Limiting

Redis sliding window. Her kullanıcı için:

| Resource | Limit | Pencere |
|---|---|---|
| LLM çağrı (generate) | 10 | 60s |
| Citation verify | 50 | 60s |
| Auth (login) | 5 | 5dk (per IP) |
| Public API (calls) | 60 | 60s |

Plan-bazlı limitler:
- Starter: 3 proposal/ay
- Pro: 15 proposal/ay
- Agency: sınırsız (ama maliyet alarmı)

Rate limit aşıldığında 429 + `Retry-After` header. UI'da toast: "Çok hızlı gidiyorsunuz, X saniye sonra tekrar deneyin."

## 9. Audit Log

`audit_log` tablosuna yazılan eventler:
- `auth.login`, `auth.login_failed`, `auth.logout`, `auth.password_reset`
- `tenant.member_invited`, `tenant.member_added`, `tenant.member_removed`, `tenant.role_changed`
- `tenant.llm_config_updated` (anahtar değer YOK, sadece "set/unset" event)
- `proposal.created`, `proposal.updated`, `proposal.exported`, `proposal.archived`
- `compliance.validation_run`, `citation.verified`
- `billing.subscription_created`, `billing.subscription_cancelled`

Saklama: 90 gün, sonra hard delete (yasal min süre yok bizim için, ama 90 gün incident response için yeterli).

Admin UI'da audit log görünüm sayfası Faz 2'de (`/settings/audit`); MVP'de SQL ile bakılır.
